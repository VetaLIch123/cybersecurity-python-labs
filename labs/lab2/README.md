# Лабораторна робота №2

## Варіант

**Варіант 4 — аналіз журналу автентифікації SSH/Linux.** Аналізатор шукає IP-адреси, з яких за задане часове вікно було більше невдалих спроб входу, ніж указаний поріг.

## Структура

```text
labs/lab2/
├── __init__.py
├── main.py
├── Task1.py
├── Task2.py
├── README.md
└── data/
    └── data_v04/
        └── auth.log
```

`Task1.py` містить класи користувача, адміністратора, сесії, журналу аудиту та облікового запису. `Task2.py` реалізує аналізатор `auth.log`. Вхідний журнал для варіанта 4 розміщений у `data/data_v04/auth.log`.

## Підготовка

Потрібен Python 3.10 або новіший. Із кореня репозиторію встановіть залежності:

```bash
pip install -r requirements.txt
```

`requirements.txt` містить Ruff для перевірки та форматування коду; обидва завдання використовують стандартну бібліотеку Python.

## Запуск

Команди виконуйте з кореня репозиторію `cybersecurity-python-labs`.

Запуск `main.py` без аргументів послідовно виконує демонстрацію Завдання 1 та аналіз журналу Завдання 2 зі стандартними параметрами:

```bash
python labs/lab2/main.py
```

Окремо запустити демонстрацію ООП:

```bash
python labs/lab2/main.py demo
```

Окремо запустити аналіз журналу:

```bash
python labs/lab2/main.py analyze
```

Приклад аналізу зі зміненим порогом і збереженням JSON-звіту:

```bash
python labs/lab2/main.py analyze --auth-log labs/lab2/data/data_v04/auth.log --threshold 5 --window-min 5 --output-json labs/lab2/data/data_v04/bruteforce_report.json
```

## Параметри аналізатора

| Параметр | Призначення | За замовчуванням |
| --- | --- | --- |
| `--auth-log` | Шлях до файлу SSH/Linux auth log | `labs/lab2/data/data_v04/auth.log` |
| `--threshold` | Поріг невдалих спроб; сповіщення виникає, коли кількість **перевищує** поріг | `5` |
| `--window-min` | Тривалість часового вікна у хвилинах | `5` |
| `--output-json` | Шлях для збереження JSON-звіту; якщо не задано, звіт друкується лише в консолі | Не задано |

Парсер враховує події `Failed password` та `Accepted password`, зчитує IP, ім'я користувача й час. У звіті показуються підозрілі серії та IP-адреси, які рекомендується блокувати. Програма лише формує рекомендацію і сама мережеві правила не змінює.

У форматі syslog у наданому `auth.log` рік і часовий пояс відсутні. Для відображення часу програма підставляє поточний рік; часові мітки залишаються без часового поясу.

## Поведінка при помилках

- Якщо файл журналу не вдається відкрити, причина записується через `logging.error`, аналіз завершується з кодом помилки.
- Якщо `threshold` або `window-min` не є додатними числами, аналіз завершується з повідомленням про помилку.
- Рядки, які не містять розпізнаваної події автентифікації або коректної IP-адреси й часової мітки, пропускаються.
- Якщо знайдено підозрілу серію, вона записується в лог на рівні `ERROR` згідно з вимогою завдання; це сповіщення про загрозу, а не аварійне завершення програми.
- Якщо JSON-звіт не вдається записати, причина виводиться в лог, а команда завершується з кодом помилки.
